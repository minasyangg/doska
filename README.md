# Доска для онлайн-занятий

Бесконечное полотно с рукописным вводом и синхронизацией в реальном времени.
Учитель и ученик заходят своими аккаунтами mcko-app, доски живут, пока их не
удалят, у каждой — свой список участников и своё хранилище картинок.

## Установка на своём компьютере

Нужен Node.js 20.6 или новее — https://nodejs.org

```bash
npm install
cp .env.dev.local.example .env.dev.local   # и заполнить, см. ниже
npm run dev
```

Откройте http://localhost:8080 — попадёте на экран входа.

### Переменные окружения

`npm run dev` читает их из `.env.dev.local` (файл в `.gitignore`, шаблон рядом).
На сервере то же самое задаётся обычными переменными окружения и запускается
через `npm start`.

| Переменная | Зачем |
|---|---|
| `SUPABASE_URL` | Проект Supabase, общий с mcko-app. Доска не хранит в нём ничего своего сверх таблиц `doska_*`. |
| `SUPABASE_ANON_KEY` | Publishable-ключ (`sb_publishable_…`). Именно он, а не legacy anon: legacy в проекте отключён. |
| `SESSION_SECRET` | Ключ шифрования сессий, от 32 символов. Без него доска поднимется на временном ключе и все входы слетят при перезапуске. |
| `DOSKA_SSO_SECRET` | Общий секрет с mcko-app для перехода по кнопке «Доска». Без него работает только вход почтой и паролем. |
| `MCKO_URL` | Адрес mcko-app для обратного направления: пришедшего по ссылке без сессии доска отправит туда за личностью. Пусто — всегда своя форма входа. |
| `PORT` | По умолчанию 8080. Должен совпадать с `DOSKA_URL` в mcko-app. |
| `DATA_DIR` | Куда класть доски и картинки. Пусто — `./data` рядом с `server.js`. |
| `TRUST_PROXY=1` | За обратным прокси: брать протокол из `X-Forwarded-Proto`, иначе кука не получит флаг `Secure`. |

## Что где

```
server.js          сервер: маршруты, комнаты, синхронизация
lib/gotrue.js      пять запросов к Supabase Auth (вместо SDK)
lib/db.js          БД mcko-app через PostgREST — всегда токеном пользователя
lib/session.js     сессии: кука + зашифрованные токены на диске
lib/store.js       содержимое досок: журнал операций и снимки
lib/points.js      плотная укладка точек в памяти
lib/capability.js  кто что может делать с доской
public/index.html  клиент целиком: движок пера, интерфейс, сеть
data/boards/<id>/  содержимое доски: snap.json + log.ndjson
data/files/<id>/   вставленные картинки, по каталогу на доску
data/sessions/     сессии (зашифрованы AES-256-GCM)
data/trash/        удалённые доски, лежат месяц
```

Папка `data/` создаётся сама. Резервная копия — это её копия **плюс** дамп
таблиц `doska_*` в Supabase: без них доска не поймёт, кому что принадлежит.

## Как хранится написанное

Доска целиком живёт в памяти процесса, пока в ней кто-то есть. На диск она
попадает двумя разными способами, и это главное, что стоит понимать.

**Журнал.** Каждая правка — новый объект, сдвиг, стирание, замок — дописывается
строкой в конец `log.ndjson`. Стоимость записи равна размеру правки, а не
размеру доски, поэтому час занятия обходится не дороже первой минуты. Строки
копятся не дольше 150 мс, так что падение процесса стоит максимум последнего
мазка.

**Снимок.** Когда журнал перерастает 512 КБ или 2000 операций, а также когда
из доски выходит последний участник, состояние сохраняется целиком в
`snap.json`, и журнал обнуляется. Снимок пишется во временный файл и
переименовывается, и только после этого журнал усекается: если процесс умрёт
между этими шагами, останется свежий снимок и уже лишний журнал — при загрузке
операции, чей номер не больше номера снимка, отбрасываются, и состояние
сходится.

**Загрузка** — это снимок плюс проигрывание журнала. Оборванная последняя
строка (запись не долетела при падении) отбрасывается: строки самодостаточны,
и потеря хвоста стоит одной операции, а не всей доски.

Доски в старом формате (один файл `<id>.json`) читаются как есть и переезжают
в новый при первом же снимке — делать ничего не нужно.

## Точки в памяти

Точка — это две координаты и нажим. Отдельным массивом `[x, y, p]` она стоит
около 82 байт: три числа по восемь и почти семьдесят байт служебных заголовков.
Занятие на полтора миллиона точек весило 120 МБ, полная доска — 480.

Уложенные подряд в `Float32Array` те же три числа занимают двенадцать байт.
По проводу и на диске формат прежний, `[[x,y,p], …]`; разворачиваются точки на
границе — в `lib/points.js`. Поэтому старые снимки читаются как есть.

Снимок прореживает не только то, что уходит на диск, но и саму комнату: после
первого же уплотнения занятие занимает 7 МБ вместо 120.

| | было | стало |
|---|---|---|
| занятие, 1.5 млн точек, идёт урок | 120 МБ | 23 МБ |
| оно же после первого снимка | 120 МБ | 7 МБ |
| потолок в 80 000 объектов | 480 МБ | 28 МБ |

Округление при развороте обязательно: `315.05` после обхода через float32
становится `315.04998779296875`, и в JSON такое число занимает втрое больше
места.

Клиент прореживает штрих сам, при отрыве пера: на сервер уходит около семидесяти
точек вместо четырёхсот, и ровно столько же остаётся в памяти вкладки. Допуск
там считается в экранных пикселях, а не в мировых, — иначе штрих, начатый с
приближением, заметно осел бы сразу после отрыва пера.

**Потолок объектов** — 80 000 на доску, меняется переменной `MAX_ITEMS`. При
переполнении доска перестаёт принимать новое и говорит об этом. Раньше она
молча выбрасывала две тысячи самых старых объектов — то есть начало занятия
исчезало, и человек узнавал об этом, только пролистав наверх.

**Удаление ничего не стирает.** В базе строка лишь помечается удалённой, и
содержимое ведёт себя так же: каталог доски и её картинки уезжают в
`data/trash/<id>_<дата>/`, откуда их можно достать руками. Через месяц уборщик
их убирает.

## Меню по правой кнопке

Щелчок правой кнопкой открывает меню; протяжка правой кнопкой по-прежнему тянет
холст — различаются по тому, сдвинулась ли рука. Щелчок по объекту вне выделения
сначала выделяет его, как во всех редакторах.

На объекте: дублировать, копировать, вырезать, вставить, группировать и
разгруппировать, повернуть на прямой угол в обе стороны, на передний и на задний
план, заблокировать, удалить. На пустом месте: вставить, выделить всё и выбор
фона.

Над самим выделением остались только два значка — замок и корзина. Это то, что
нужно под рукой каждую минуту; остальное живёт в меню и на клавишах. Замок
открыт или закрыт — по нему и видно состояние. На время жеста панель убирается:
она висит над рамкой и, пока объект тащат или поворачивают, только закрывает
его и подсовывает корзину под руку.

Размер и поворот мышью — за ручки на рамке: восемь квадратов (углы держат
пропорции, середины сторон тянут по одной оси) и точка поворота над верхним
краем.

**Группы.** Объекты одной группы ходят вместе: щёлкнули по одному — выделились
все. Группа хранится полем `g` у каждого объекта, а не отдельной сущностью:
переносить, копировать и удалять её тогда не нужно учить отдельно. Копия группы
получает новое имя, иначе слиплась бы с оригиналом.

**Слои.** Кто выше кого, решает порядок в массиве объектов. Картинки при этом
рисуются под записями, чтобы вставленный снимок не закрыл написанное; «на
передний план» поднимает конкретную картинку и оттуда — прямая просьба сильнее
умолчания.

**Буфер обмена** свой, не системный: в системном нельзя держать наши объекты.
Картинку из системного доска принимает как и раньше — обычной вставкой.

## Настройки пера

Правая кнопка по карандашу или маркеру открывает настройки. Кроме цвета и
толщины там две вещи про руку.

**Чувствительность мыши.** Линия тянется за указателем не мгновенно: каждая
новая точка ставится не там, где мышь, а на доле пути к ней. Это гасит дрожание
— мышью иначе получается «пила». Доля и есть чувствительность: на ста процентах
линия идёт след в след и повторяет каждое подрагивание, ниже — мягче и
спокойнее.

**Толщина от скорости.** У стилуса нажим приходит от устройства, у мыши и пальца
его нет, поэтому толщина выводится из скорости: ведёшь быстро — линия тоньше. На
нуле линия совсем ровная.

Обе настройки запоминаются в браузере: это привычка руки конкретного человека, а
не свойство занятия.

## Картинки

На доску попадают только снимки экрана и фотографии — через буфер обмена или
перетаскиванием. Из буфера они приходят в PNG, а для снимка экрана это впустую:
браузер перекодирует их в WebP при q0.85 (вдвое-впятеро меньше, расхождение
меньше полутора уровней яркости из 255) и ужимает длинную сторону до 2560,
чтобы снимок с экрана 4K не лежал целиком. Если перекодирование не выиграло —
а на мелких картинках PNG иногда лучше — уходит исходник.

Всё это делает браузер: серверу не нужны графические библиотеки, а по сети
идёт уже сжатое.

Имя файла — отпечаток его содержимого (sha256). Один и тот же скриншот,
вставленный дважды, ложится одним файлом. Загрузка отмечается в журнале
строкой `img`; появление картинки на доске — обычной операцией `add`, как у
любого другого объекта.

Картинки, на которые никто не ссылается, убираются через сутки после того, как
из доски вышел последний: сутки — потому что стёртую картинку ещё можно вернуть
отменой.

## Вход и права

Вход общий с mcko-app: та же почта и тот же пароль. Своей регистрации у доски
нет — аккаунты заводит mcko-app.

Токены Supabase в браузер не попадают вообще. При входе доска заводит свою
сессию: в куке только её идентификатор (`HttpOnly`, `SameSite=Lax`, `Secure`
под HTTPS), а пара токенов лежит на сервере зашифрованной. Своя пара, а не
проброшенная из mcko-app, — потому что ротация refresh-токенов включена, и
общий токен означал бы, что доска и mcko-app гасят сессии друг друга.

Из mcko-app есть бесшовный переход: кнопка «Доска» у учителя и ссылки в
кабинете ученика ведут на `/api/doska/open`, оттуда — одноразовый тикет на
60 секунд, и человек попадает на доску уже вошедшим.

То же работает и в обратную сторону, ради присланной ученику голой ссылки. Если
человек открыл `/board/<id>`, а сессии доски у него нет, доска не показывает
форму, а уводит его в mcko-app по `MCKO_URL`. Тот, кто уже вошёл в личный
кабинет, вернётся на ту же доску, ничего не вводя; кто не вошёл — увидит вход
mcko-app и после него попадёт туда же. Вторая попытка подряд не делается: если
вернулись всё так же без сессии, доска показывает свою форму со внятным
сообщением, иначе вкладка ходила бы между двумя сайтами по кругу. Корень `/`
в mcko-app не уводит никогда — у пришедшего может вовсе не быть там аккаунта;
для него на экране входа есть кнопка «Войти через МЦКО».

**Права на доске** разрешаются так (первое подходящее):

| Кто | Что может |
|---|---|
| Владелец (учитель, создавший доску) | всё: рисовать, стирать любое, переименовывать, запрещать рисование, менять доступ, удалить доску |
| Участник с уровнем «рисует» | рисовать, двигать и стирать своё; чужое — только если владелец разрешил |
| Участник с уровнем «смотрит» | смотреть, масштабировать, включить «Следовать» |
| Админ организации | видит все доски организации и открывает их только на просмотр |
| Гость по ссылке | смотреть или рисовать — как выбрал владелец; по умолчанию гостевая ссылка выключена |
| Все остальные | ничего: доска не открывается |

Всё это проверяется не доской, а RLS в Supabase (`041_doska_boards.sql`):
доска ходит в базу токеном самого пользователя и сервисного ключа не имеет.
Добавить в участники можно только своего ученика — это проверяет
`check_student_owned_by_auth`, та же функция, что и в остальном mcko-app.

Права перепроверяются раз в минуту, поэтому отзыв участника доходит до
открытой вкладки в течение минуты, а не к концу занятия.

Звука и видео здесь нет намеренно. Держите параллельно привычный звонок.

## Управление

| Действие | Как |
|---|---|
| Масштаб | колесо мыши, кнопки −/+ справа снизу, клавиши +/− |
| Панорама | Shift+колесо, пробел с перетаскиванием, средняя кнопка, инструмент «рука» |
| Вставить скриншот | Ctrl+V, либо перетащить файл картинки на доску |
| Двигать, растягивать, вращать объект | инструмент «выделить» (4), тянуть за ручки |
| Выделить несколько | тем же инструментом протянуть рамку по пустому месту; Shift — добрать или убрать; Ctrl+A — всё своё |
| Дублировать выделенное | Ctrl+D |
| Удалить выделенное | Delete |
| Фон: клетка → точки → линейка → чистый лист | кнопка сетки или клавиша G |
| Инструменты | 1 карандаш, 2 маркер, 3 ластик, 4 выделить, 5 рука, 6 фигура |
| Настройки инструмента (цвет, толщина, заливка) | правая кнопка по его значку или повторное нажатие по уже выбранному |
| Фигуры и линии | значок фигур в панели раскрывает список; напрямую: R прямоугольник, O эллипс, L линия, A стрелка, N ломаная, C кривая, M многоугольник; Enter — завершить, Esc — отменить |
| Отменить, вернуть | Ctrl+Z, Ctrl+Shift+Z |
| В начало координат | клавиша 0 или кнопка ⌂ |

Сетка адаптивная: шаг клетки сам меняется при масштабировании. Настройка фона
своя у каждого участника и на общую доску не влияет.

Картинки всегда рисуются под рукописным текстом — вставленный скриншот не
закроет то, что уже написано.

## Размещение в интернете

Сервер должен работать по HTTPS: браузеры разрешают защищённые сокеты
(`wss://`) только со страниц, открытых по `https://`. Куке сессии флаг `Secure`
тоже нужен, а за прокси для этого понадобится `TRUST_PROXY=1`.

### Готовый хостинг

Render, Railway, Fly.io: команда установки `npm install`, запуск `npm start`,
порт из `PORT`. Два подводных камня на бесплатных тарифах:

1. Сервис засыпает при простое и просыпается 20–50 секунд.
2. Файловая система сбрасывается при обновлении, и `data/` исчезнет вместе с
   досками, картинками и сессиями. Подключите постоянный диск и задайте
   `DATA_DIR=/data`.

### Свой сервер

VPS, домен и Caddy как обратный прокси — сертификат он получает сам:

```
doska.example.com {
    reverse_proxy localhost:8080
}
```

Держать живым через `pm2 start server.js` или юнит systemd. Место под картинки:
считайте 1–3 МБ на скриншот, на доску отведено 200 МБ.

## Чего пока нет

- Текста с клавиатуры и редактора формул.
- PDF на доске.
- Ластик удаляет линию целиком, а не её часть.
- Отмена локальная: Ctrl+Z убирает ваше последнее действие. Если двое
  одновременно пишут в одном месте, порядок объектов может слегка разойтись.
  Лечится переходом на CRDT (Yjs) — это отдельная работа.
- Комфортно примерно до 10–15 участников и десятков тысяч объектов на доске.

## Если что-то не работает

**Не пускает по правильному паролю.** Проверьте `SUPABASE_URL` и
`SUPABASE_ANON_KEY`: ключ должен быть publishable (`sb_publishable_…`), legacy
anon в проекте отключён и отвечает 401 с пустым телом.

**Вход слетает после каждого перезапуска.** Не задан `SESSION_SECRET` —
доска работает на временном ключе и не может расшифровать старые сессии.

**Кнопка «Доска» в mcko-app ведёт на экран входа.** Не совпадают
`DOSKA_SSO_SECRET` на двух сторонах, либо тикет протух: он живёт 60 секунд и
гасится при первом использовании.

**Ученик видит доску, но рисунки не появляются.** Почти всегда это HTTPS:
страница открыта по `https://`, а сокет идёт по `ws://`. Проверьте, что прокси
пропускает WebSocket (Caddy пропускает по умолчанию).

**Скриншот не вставляется.** В буфере должна быть именно картинка, а не файл
из проводника. Поддерживаются PNG, JPEG, WebP, GIF до 16 МБ.
